## A1. Scope оценки
Полный цикл по списку «делала команда» из SYSTEM.md §6: фаза вникания в
домен и выбора архитектуры/технологий (~1–2 месяца) + дизайн + разработка +
тестирование + вывод в прод новой версии кор-функционала на замену первой
версии.
- Входит: воркеры рендеринга и OCR, кластер с механизмом контроля
  доставки (вочдоги + токены), NOC, юзер-портал, парсер входящих email,
  сохранение CDR/данных для биллинга, интеграционные тесты на реальном
  потоке со сравнением со старой системой.
- **Не входит:** софт PoP'ов, программа раутинга, биллинг, эксплуатация
  после запуска, разработка первой версии системы.

## A2. Definition of Done
Новая система принимает боевой трафик в проде; интеграционные тесты на
реальном потоке пройдены, результаты сходятся со старой системой; старая
версия может быть выведена из эксплуатации.

## A3. Команда и стартовые условия
Команда **домена не знала** — вникание в предметную область, обсуждения
и выбор технологий заняли ~1–2 месяца (входит в A1). Смягчающий фактор:
существует работающая v1 как живой референс требований («как v1, но
исправить то, что не устраивает») — полномасштабного сбора требований
с нуля нет, но домен (факс-протоколы, телеком, распределённая доставка)
для команды новый. Состав blended, включая QA и PM. Численность команды
в допущения **не входит** (оценивается объём работ, не календарь).

## A4. Переиспользование
Кода первой версии в новой нет («никаких референсных базовых классов»).
Переиспользуются: готовый софт PoP'ов, готовый раутинг, сторонняя
OCR-библиотека, рендеринг через printer-driver (Black Ice-класс),
существующая инфраструктура хранения (Lustre) и БД как технологии —
их не разрабатываем, только интегрируемся.

## A5. Технологическая эпоха
2007–2009: C#/.NET ~3.x, Windows-кластер на собственном железе, без
облаков и без готовых оркестраторов (то, что сегодня дал бы брокер
сообщений/Kubernetes, пишется руками — вочдоги, токены, контроль
доставки). MSMQ осознанно исключён по негативному опыту v1.

## A6. Целевой масштаб
Инженерный target — **~1 млн факсов / 10-часовой день (~30/с в среднем)**,
с burst до ~10× (**~300/с**, «10 млн/день» — оценка пикового режима).
Кластер ~16–20 нод, 10–20 PoP'ов. Оценка делается под проектирование
на номинал с устойчивостью к burst: распределённость, переживание сбоев
и контроль доставки каждого факса — обязательные свойства, а не опции.

## A7. Форматы рендеринга
8–10 входных форматов (DOC, XLS, PPT, PDF, TXT, GIF, TIFF + возможно
1–3 забытых). Каждый формат — отдельная работа по интеграции и
стабилизации рендерера, не «бесплатное» расширение списка.

## A8. Организационный контекст
Продуктовая компания (Venali), внутренняя переделка по решению
руководства. Жёсткого дедлайна нет, давление есть. Процесс — фаза
планирования, затем скрам. Согласования внутренние, быстрее
enterprise-заказчика из примера BMS. Учитывается в reference class
(decomposition по конструкции это не видит).

## A9. Единицы
Оценка в **person-months** (1 pm ≈ 21 pd ≈ 168 часов), суммарные
трудозатраты всей команды, включая QA/PM и фазу выбора архитектуры.
Перевод в календарную длительность — отдельный шаг, не входит в прогоны.
