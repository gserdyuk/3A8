## 5. Doubts

**Enumeration doubts:**

1. **A077, A122 (sizing):** "GIN record" / "LN record" could count as a kind the store owns, which gives 4 (L). The same happens if required and non-required are read as two kinds. Either one crosses the M/L boundary.
2. **A077, A122 (special count):** industry could be set up at run time instead of loaded. That gives 2, still M.
3. **A078, A123:**
   - Counting "through a step-by-step wizard" as its own action gives 6 (L).
   - Treating "via import" and "by cloning" as mere ways of "create" gives 4 (L).
   - Counting every way separately (create individually, via import, via wizard, by cloning; edit manually, via import; import from external system; map) gives 8 (XL).
   - "Create and manage data" in P-19 / L-15 is done in the external system, so I left it out. Counting it adds 2.
4. **A086:** "evaluate record status" could be a separate action, giving 2 (M). "Some attributes" names none (P-5).
5. **A096, A125:** "potential duplicate records" could be read as already covering the matching. That removes "match", giving 3 (M), which crosses the L/M boundary.
6. **A101:** reading the four statuses as one "assign status" action gives 2 (M). Splitting system assignment from user assignment gives 6 (L). "Currently" suggests the status list may change.
7. **A103, A127:** the set of record statuses is never named. I counted only the named verb. Counting one action per status, as in A101, cannot be done from the declaration.
8. **A105, A128:** splitting "by industry" and "by product type" into separate rule actions gives 4 (L) for A105 only. Merging the two date displays gives 2, still M for both.
9. **A109 (sizing):** reading each / case / pallet as kinds, or counting a separate parent-child link, gives 4 or more (L).
10. **A109 (special count):** pre-defined levels could be configured fresh instead of loaded. That gives 2, still M.
11. **A110:** a single "check physical fit" action gives 1 (S).
12. **A115:**
    - Counting the four named symbologies as separate generate actions gives 7 (XL).
    - Counting "select size" (from "selectable sizes") gives 5 (L).
13. **A116:** if generating is a service step rather than a user task, the count is 1 (S).
14. **A117:** counting PNG and SVG export as separate tasks gives 3, still M.
15. **A118:** 6 is the top of L. Counting "select the record" (from "for each record") gives 7 (XL).
16. **A119:** counting "create template" (the name word "library") gives 3, still M.
17. **A120:** if "create a digital GIN" is taken to cover both the QR and the markup words, the count is 1 (S).
18. **A124:** counting "decide by industry whether the pool applies" gives 2 (M).
19. **A126:** the LN status set is never named, unlike A101. Only the named verbs were counted.
20. **A129 (sizing):** counting "organising attribute" as a store-owned kind gives 4 (L). I read it as owned by A122.
21. **A129 (special count):** treating level as a derived depth, not a loaded kind, gives 2, still M.
22. **A130:** counting "extend hierarchy to any depth" as an action gives 2 (M).
23. **A131:** counting outcome or verifier as kinds gives 2 or 3 (M) for sizing. The special count is unchanged.
24. **A132:** if L-13 is read as covering the due list, the count is 1 (S).

**Contradictions between obligations (named, not resolved):**

25. **P-10.1 / L-9.1:** "the system or the user assigns a status" conflicts with "status may update to reflect record status". The obligations don't say which wins when a user-set status disagrees with the automatic update.
26. **P-5.1 against P-5 / L-5:** frozen attributes "cannot be edited", but edit via import is allowed. The obligations don't say whether import bypasses the freeze.
27. **P-11.1 against P-11.4:** hierarchies have pre-defined levels, but a user can change an item's level while building. The obligations don't say whether the change is limited to the pre-defined levels.
