# INPUT 1 — the project, in brief

An RFP (September 2018) from a large not-for-profit standards organisation ("X-Customer", 200 000+ member companies in 25 industries, USA) for a **Member Application Solution**: a web-based B2B application in three integrated modules — **Product** (create and manage 12/14-digit Global Item Numbers, GIN, with barcodes, hierarchies each→case→pallet, product sheets, images), **Location** (13-digit Location Numbers, LN, unlimited-depth hierarchies, annual verification), **Access Data** (search, view, export prefix/GIN/LN data — the subscribe side of a publish-and-subscribe model, with a public anonymous tier). Cross-cutting: company-admin user administration with four named roles on top of an enterprise identity provider (claims-based SSO, protocol not yet chosen); record approval workflow and validation against standards and business rules "to be defined as part of the project"; import/export in six file formats plus a member REST API under the client's 3scale API management; reports with scheduling and history; notifications by email, SMS and onscreen; a non-transactional read store fed near-real-time from the transactional store; migration of the current applications' data and users; four environments; 99.9% availability with tested failover, backup/DR procedures, security design; response-time targets at stated concurrency; WCAG 2.0 A; IE9+ and current browsers. Volumes today: 500 000 prefixes, 10 million GINs, 550 000 LNs; 38 000 users growing to 256 000 by 2024. The vendor (an outsourcing company) performs requirements and design, development and testing, implementation, and post-production support and transition. Contract covers design, development, testing and acceptance.

**Case profile, pinned before any run:** team middle/senior mix, one team at one site, first system in this domain for the team; client approval cadence that of an enterprise. No outcome is known for this case.
