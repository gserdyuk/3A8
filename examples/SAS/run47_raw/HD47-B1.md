## 5. Doubts

**D-1 — GIN / LN parallelism (systematic, affects almost every row).** Nearly every element covers a matched pair of obligations, one for GIN (P-…) and one for LN (L-…), with identical wording bar the identifier family. I read the subtree's own name — *Shared record core* — as declaring these one action on one object ("a record", "an identifier") and counted each once. Read the other way, with GIN and LN as distinct objects, **every affected count doubles** and most classes rise by one or two steps. This is the single largest free reading in the batch and I have not resolved it beyond the stated reading.

**D-2 — A-070, the import channel.** P-1 / L-1 name four creation channels: individually, via import, via wizard, by cloning. Wizard and cloning have their own sibling elements; import has none in this batch. The parenthetical "(individual entry)" in the element name is why I excluded import. If import belongs to A-070, the count is 2 → **M** rather than S.

**D-4 — A-076, the automatic check digit.** "a check digit is assigned automatically" (P-2 / L-2) is counted on A-004, whose declared content is the check-digit rule. It could as fairly be counted on the assignment service that performs the assignment, giving A-076 a count of 4 → **L**.
