# Doubts

1. **D5 as a separate ILF** — pick-up/drop-off locations could instead be a RET of D2 (both are "initially defined/loaded from CTC" and amendable in the same portals); merging would make D2 RET 2, still Low.
2. **T29 / D14 (SSO)** — authentication is often excluded from a functional count as pure infrastructure; counted here because the assertion is control information altering system behavior. Could go the other way entirely.
3. **D13 (Uber)** — an on-demand booking API is arguably a transactional interface only, not a referenced file; D13 could vanish, leaving T19 at FTR 2 (still Low).
4. **D11 (UPSA)** — the RFP gives the integration no content and no direction; it could be an output feed *to* UPSA (an EO, no EIF) rather than a referenced file. Classified on the minimal reading; severely under-enumerated.
5. **T7 and T9 dedup** — the Employees Portal and Administration Portal amendments are read as identical processing from two entry points; if the processing differs, each is two EIs.
6. **T16/T17** — email and SMS could be one elementary process with channel as a data element; kept separate because the RFP states them as separate obligations with distinct delivery mechanics (A5).
7. **T12/T13/T14** — each decision pair (Accept/Reject, Approve/Decline) is read as one EI with an outcome element; one-EI-per-outcome would raise the EI count without changing any class.
8. **T33/T34 as EQ** — "reporting" may in practice involve aggregation (derived data), which would make them EOs; no derivation is named, so retrieval was taken.
9. **R28 outside scope** — could instead be a workflow-configuration EI on D7; the text reads as a design-for-change quality, so it was excluded.
10. **T32 vs T26** — the Travel Manager's status view could be the same inquiry as the employee's; kept separate because scope (all bookings vs own) differs.
11. **T18/T19/T20/T21 band edges** — the enumerable DETs sit at 4–5; any realistic booking form or API payload has more fields, which would lift these to Average. The class follows the enumeration, so Low stands.
12. **T23 ambiguity** — R45 may hold two obligations (identify combining opportunities; execute the combine); flagged, read as one, not split.
13. **T15 (Paid)** — payment status could arrive from CTC rather than a user, which would move its FTR set; no text decides it.
14. **No notification log** — R26/R27 imply sending, not keeping; no ILF was counted for notification history.
15. **T1 as one process** — the search over third-party systems (R15) and over manually uploaded bookings (R16) is read as one search facility; two facilities would split T1 (each at lower FTR).
16. **Contradictions** — none found that require resolution; the declared overlaps (R05 vs portals, R11/R65, R12/R13/R66/R68, R56 vs R58–R60) were handled by co-citation or scope listing, as the list's own weakness note anticipates.
