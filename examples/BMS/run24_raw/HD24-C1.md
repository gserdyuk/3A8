## 3. Special counts

**N87 · Reporting Read Model — entity kinds needing pre-load.** Verdict given per kind held:

- **Supplier records — pre-load required.** Hotel and transport suppliers must be known before any
  of them can be given access (R36, R46), upload against their own identity (R37, R47) or appear in
  a suppliers report (R59). Batch C contains no supplier-registration element, so the supplier set
  cannot come into existence through use; it must be present before first use.
- **Booking-detail records — no pre-load.** Bookings accrue through the portals at run time (R05,
  R49, R50); the read model is usable while empty and fills from use.
- **Financial records — no pre-load on the stated reading.** Financial reporting (R60) reads against
  pricing supplied by suppliers at run time (R37, R47). No reference entity (cost centre, budget
  code, chart of accounts) is named anywhere in the declared content, so none is counted.

**Count of kinds needing pre-load: 1 → S.**

## 4. Unsizeable elements

**N68 · Process Transparency (statement) — model defect M10.** The counted thing for a statement is
*systems or components the property constrains*. Neither the element's declared content ("Process
Transparency", parent root, no declared scope) nor its sole obligation R10 ("Clear business
processes") names a single system or component. The noun the property actually attaches to —
*business processes* — is not a component of this model, and the model declares no mapping from a
business process to any element. Enumerating "all portals" or "the whole system" would be a guess
about scope, not a reading of the declaration, so no class is assigned. Its **kind** is nonetheless
determinable from the same text and is recorded above as `compliance`; the kind adjudication does
not depend on the failed enumeration.
