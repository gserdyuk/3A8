## 3. Taxonomy — the standard's own components

The standard counts five component types: two **data functions** and three **transactional functions**.

**Data functions:**

- **ILF — Internal Logical File**: a user-identifiable group of logically related data or control information maintained within the boundary of the application being counted.
- **EIF — External Interface File**: a user-identifiable group of logically related data or control information referenced by the application being counted but maintained within the boundary of another application.

**Transactional functions:**

- **EI — External Input**: an elementary process that processes data or control information coming from outside the application boundary, whose primary intent is to maintain one or more ILFs and/or to alter the behavior of the system.
- **EO — External Output**: an elementary process that sends data or control information outside the boundary, whose primary intent is to present information to a user through processing logic beyond mere retrieval — it must contain at least one of: a mathematical calculation, derived data, maintenance of an ILF, or alteration of system behavior.
- **EQ — External Inquiry**: an elementary process that sends data or control information outside the boundary, whose primary intent is to present information to a user purely by retrieval of data from ILFs or EIFs — no calculation, no derived data, no ILF maintenance, no behavior alteration.

Counted quantities used by the matrices:

- **DET — Data Element Type**: a unique, user-recognizable, non-repeated attribute or field.
- **RET — Record Element Type**: a user-recognizable subgroup of data elements within an ILF or EIF.
- **FTR — File Type Referenced**: a data function (ILF or EIF) read and/or maintained by a transactional function.
