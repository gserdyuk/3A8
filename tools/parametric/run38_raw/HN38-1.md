## 2. The standard named

I state the **IFPUG Function Point Analysis (FPA)** counting practice — the method maintained by the **International Function Point Users Group** in its *Counting Practices Manual* (CPM, editions 4.x, from 4.1 through 4.3.1), which is also the substance of **ISO/IEC 20926** ("IFPUG 4.x unadjusted functional size measurement method"). The numeric tables below (complexity thresholds and weights) are stable across the 4.x editions.

Variants that exist and are **not** what I state:

- **NESMA** (ISO/IEC 24570) — a Dutch sibling nearly identical to IFPUG in these tables; also defines "estimated" and "indicative" simplified counts that bypass the complexity matrices.
- **FiSMA** (ISO/IEC 29881) — a different structure entirely.
- **COSMIC** (ISO/IEC 19761) — not weight-table based at all; measures data movements.
- **Mark II FPA** (ISO/IEC 20968) — UK variant with a different formula and no Low/Average/High matrices.
- **Simple Function Points (SFP / SiFP)**, adopted by IFPUG alongside classic FPA — collapses the taxonomy and drops the complexity matrices.

## 3. Taxonomy — the standard's own components

The standard partitions functionality into **five component types**: two data functions and three transactional functions.

**Data functions**

- **ILF — Internal Logical File**: a user-identifiable group of logically related data or control information maintained within the boundary of the application being counted.
- **EIF — External Interface File**: a user-identifiable group of logically related data or control information referenced by the application but maintained within the boundary of a *different* application.

**Transactional functions**

- **EI — External Input**: an elementary process that processes data or control information coming from outside the boundary, whose primary intent is to maintain one or more ILFs and/or to alter the behavior of the system.
- **EO — External Output**: an elementary process that sends data or control information outside the boundary, whose primary intent includes processing logic beyond mere retrieval — at least one of: a calculation, derived data, maintaining an ILF, or altering system behavior.
- **EQ — External Inquiry**: an elementary process that sends data or control information outside the boundary, whose primary intent is to present information to a user through *retrieval only* — no calculation, no derived data, no ILF maintenance, no behavior alteration.

The counted quantities the standard uses to grade complexity:

- **DET — Data Element Type**: a unique, user-recognizable, non-repeated field.
- **RET — Record Element Type**: a user-recognizable subgroup of data elements within an ILF or EIF (used for data functions only).
- **FTR — File Type Referenced**: an ILF or EIF read and/or maintained by a transaction (used for transactional functions only).
